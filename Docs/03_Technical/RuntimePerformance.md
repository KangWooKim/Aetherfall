## 측정 질문과 대상

첫 전투 조우에서 이동·공격·라운드 재시작을 반복할 때 **60 FPS 제한 아래 프레임 간격과 스레드·GPU 시간, 프로세스 메모리가 어떻게 나타나는지** 관측합니다. 측정 ID는 `AF-20260909-FinalSource-ForestIntro`이며, 2026년 9월 9일 독립 프로세스 3회에서 각각 1,800개 프레임 표본을 집계합니다.

대상 소스 커밋은 `e462c536c195a16b46e526dab94c8d6170275e0c`입니다. 측정은 원본 프로젝트의 Editor Development 모듈을 사용합니다. 이 소스에는 UE 5.4 로딩 화면의 Slate 포함 경로·CoreTicker 형식과, 믹스 적용 전에 동적 UI SoundClass를 오디오 장치에 등록하는 처리가 포함됩니다. [설정 및 오디오 적용 흐름](CoreTechnologies.md#6-일시-정지-중-그래픽-설정-확인-시간-관리)에서 관련 구현을 설명합니다.

세 실행의 계산 FPS는 58.88–59.89 FPS입니다. 이는 아래 조건에서 얻은 짧은 **프레임 페이싱 관측**입니다. 시작 시 엔진의 렌더 스레드 경고가 남아 있으며 오류가 없는 기준 성능, 최대 처리량이나 최적화 개선율을 뜻하지 않습니다.

## 입력과 측정 구간

기존 엔진 CSV Profiler와 Enhanced Input 콘솔 명령을 사용합니다. 다음은 실제 인자 구성이며 로컬 경로만 변수로 표시합니다. 가독성을 위해 줄을 나누었고 실제 실행에서는 각 항목을 하나의 인자로 전달합니다.

```text
<UE_ROOT>/Engine/Binaries/Win64/UnrealEditor.exe <ORIGINAL_PROJECT>/Aetherfall.uproject
/Game/Aetherfall/Maps/M_VerticalSlice -game -d3d12 -windowed -ResX=1280 -ResY=720
-WinX=40 -WinY=60 -unattended -nosplash -NoVSync -LiveCoding=false
-UserDir=<RUN_USER_DIR> -abslog=<RUN_LOG> -stdout -FullStdOutLogOutput
-csvCaptureFrames=3780 -csvGpuStats -ExitAfterCsvProfiling
-ExecCmds="t.MaxFPS 60,r.VSync 0,r.SetRes 1280x720w,r.ScreenPercentage 100,
sg.ViewDistanceQuality 2,sg.AntiAliasingQuality 2,sg.ShadowQuality 2,
sg.GlobalIlluminationQuality 2,sg.ReflectionQuality 2,sg.PostProcessQuality 2,
sg.TextureQuality 2,sg.EffectsQuality 2,sg.FoliageQuality 2,sg.ShadingQuality 2,
t.IdleWhenNotForeground 0" -csvExecCmds="<아래 프레임별 명령>"
```

캡처 프레임 300에서 `Input.+key W`, 660에서 `Input.-key W`를 실행하여 조우에 진입합니다. 이후 1200·1800·2400·3000을 기준 프레임으로 다음 입력을 반복합니다. 누름은 `Input.+key`, 놓음은 `Input.-key`이며 W 외에는 2프레임 뒤에 놓습니다.

| 기준 프레임 이후 | 입력 |
| --- | --- |
| 0 / 10 | R로 라운드 재시작, Tab으로 락온을 요청합니다. |
| 40–80 | W로 접근합니다. |
| 100 / 160 / 240 | E 강공격, LeftMouseButton 약공격, E 강공격을 요청합니다. |
| 330 / 420 | X 검기, Q 패리를 요청합니다. |
| 460 / 520 / 540 | 약공격, SpaceBar 회피, 약공격을 요청합니다. |

1800과 3600에 `r.VSync` 조회를 기록합니다. 첫 경계가 있는 CSV 행부터 두 번째 경계 직전까지 **1,800행**을 집계합니다. 첫 헤더를 제외하고 데이터 행을 0부터 셀 때 `1799 ≤ 행 < 3599`입니다. 시작 더미 행과 앞선 준비 구간을 제외하고, 준비 중 같은 전투 입력을 한 차례 실행합니다. 29초 이상의 준비 시간을 요구하며 실제 시간은 결과 표에 적습니다.

`Shot showui`는 프레임 1680·3700, 설정·액터 조회는 1720·3660에서 실행합니다. 조회는 위 `ExecCmds`의 각 변수, `r.DynamicRes.OperationMode`, `r.AntiAliasingMethod`, `r.RayTracing`, `r.Lumen.HardwareRayTracing`을 포함합니다. 액터 조회는 다음 명령을 사용합니다. 화면 캡처와 조회는 집계 구간 밖에 둡니다.

```text
getall AetherHealthComponent CurrentHealth
getall AetherEnemyBase bHidden
getall AetherSlashProjectile bHidden
getall AetherGameModeBase PrototypeEnemySpawnCount
getall AetherGameModeBase PrototypeRoundKillGoal
getall AetherGameModeBase ActivePrototypeEncounterLabel
getall Actor bHidden
```

`ActivePrototypeEncounterLabel` 조회는 객체 이름만 출력하고 라벨 값을 제공하지 않았습니다. 조우 이름은 `Encounter triggered (ForestIntro)` 게임 로그와 HUD의 `PROGRESS ENCOUNTER FORESTINTRO` 표시를 근거로 삼습니다. 다른 수치 조회와 이 항목의 출력 범위를 구분합니다.

충돌·미완료 CSV·경계 누락·설정 불일치·조우 미진입·잘못된 소스나 모듈·핵심 표본의 0 또는 비유한 값·알려진 다른 게임이나 빌드의 동시 실행을 제외 조건으로 정합니다. 이번 성능 실행 3회는 모두 이 관측 범위에 포함하며 수치가 큰 프레임이나 사망 구간도 남깁니다. 별도 로딩·설정·풀링 기능 확인용 실행은 이 실험의 표본으로 사용하지 않습니다.

## 프레임과 처리 시간

각 실행은 1,800표본이며 총 5,400표본입니다. 평균은 산술평균, 중앙값은 가운데 두 값의 평균, p95는 오름차순 정렬한 `ceil(0.95×N)`번째 값입니다. 계산 FPS는 **1000 / 평균 FrameTime**입니다. 실행별 결과를 먼저 제시하며 서로 다른 전투 결과를 하나의 동일 부하 표본처럼 합쳐 분위수를 계산하지 않습니다.

| 실행 | 준비 / 집계(s) | 평균(ms) | 중앙값(ms) | p95(ms) | 최대(ms) | 계산 FPS |
| --- | --- | --- | --- | --- | --- | --- |
| Run01 | 30.64 / 30.19 | 16.77 | 16.66 | 18.21 | 41.10 | 59.62 |
| Run02 | 30.81 / 30.05 | 16.70 | 16.66 | 17.27 | 34.15 | 59.89 |
| Run03 | 30.62 / 30.57 | 16.98 | 16.71 | 19.71 | 67.01 | 58.88 |

| 실행 | 게임 스레드 평균 / p95(ms) | 렌더 스레드 평균 / p95(ms) | GPU 평균 / p95(ms) |
| --- | --- | --- | --- |
| Run01 | 3.60 / 5.50 | 8.12 / 15.71 | 13.17 / 16.09 |
| Run02 | 3.27 / 4.04 | 7.34 / 13.93 | 12.70 / 15.79 |
| Run03 | 3.77 / 6.91 | 10.58 / 18.16 | 13.97 / 16.69 |

`FrameTime`은 CSV의 프레임 종료 시각 사이 간격이며 제한 대기와 계측 비용을 포함합니다. `GameThreadTime`, `RenderThreadTime`, `GPUTime`은 엔진의 해당 시간 카운터를 ms로 변환한 값입니다. 특정 전투 함수의 비용이 아니며 서로 겹치는 CPU·GPU 시간을 합산하지 않습니다. 짧은 3회 결과로 지속적인 60 FPS나 다른 장면의 최대 처리량을 보장하지 않습니다. p99·1% low·개선율은 계산하지 않습니다.

## 메모리와 실제 전투 부하

필드 이름의 MB는 이 엔진 경로에서 바이트를 1024²로 나눈 값이므로 **MiB**로 표기합니다. `PhysicalUsedMB`는 프로세스 작업 집합, `VirtualUsedMB`는 Windows `PagefileUsage`를 이용한 커밋 사용량입니다. 실제 페이지 파일 I/O나 게임 객체만의 할당량이 아닙니다. `MemoryFreeMB`는 엔진이 프레임 끝에 수집한 시스템 가용 물리 메모리입니다. 피크는 측정 구간의 표본 최대값입니다.
